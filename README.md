# Sanctum Media Log

个人书影音、游戏与文化体验记录。网站只有一页：**筛选栏 + 记录表格**，支持名称／短评／标签／时期搜索、类型／状态／年份或时期组合筛选，以及点击列头排序。默认仅显示名称、类型、当前状态、最新更新日期四列。点击行或名称旁的按钮，在该行下方展开评分、短评、标签、链接、作者、书单等已有信息与完整历史，再点收起；允许同时展开多条。名称按钮支持键盘 Enter／空格操作，详情内的链接和文字选择不会触发收起。窄屏仍保留四列，极窄屏可横向滚动。页面使用一个固定的列表滚动区域；展开只更新当前行，保留点击位置和键盘焦点。列表使用普通行渲染，避免可变行高的虚拟滚动估算造成跳动。

使用现成的 Tabulator 表格组件，本地固定版本并附 MIT 许可；版本、来源和升级步骤统一记录在 [组件说明](src/vendor/tabulator/README.md)。没有导航、介绍区、年度子页面、后台或数据库；不依赖 CDN、在线 API 或外部字体。

在线查看：[书影音与文化记录](https://joo1024.github.io/sanctum-media-log/)。推送到 `main` 后，GitHub Actions 自动检查、构建并发布到 GitHub Pages。**主数据已整理为正式个人记录，虚构示例已删除；原始备份保存在仓库之外。**

## 运行与构建

需要 Node.js **22+**。网站运行、数据校验和构建使用 Node 内置模块；只有浏览器回归测试需要安装开发依赖。

```sh
npm run dev       # http://127.0.0.1:4321，修改后刷新
npm run validate  # 校验主数据
npm test          # 全项目 JS 语法、数据、筛选和构建检查
npm run fields    # 从源码读取当前类型／状态及中文名称
npm run build     # 生成 dist/
npm run preview   # 预览 dist/
```

完整验证（与发布流程一致）：

```sh
npm ci
npx playwright install chromium  # 首次安装测试浏览器
npm test
npm run build
npm run test:browser             # 桌面及手机尺寸：加载、筛选、详情、日期排序、滚动、空数据
```

浏览器测试使用 [Playwright](https://playwright.dev/docs/ci-intro)，依赖版本由 `package-lock.json` 固定。测试中的虚构记录仅拦截测试浏览器请求，不写入主数据、不进入网站构建；正式数据另有页面加载检查。CI 安装 Chromium 及系统依赖，任何检查失败都会停止发布。

不使用 npm 时，日常运行可直接执行 `node scripts/serve.mjs`、`node scripts/validate.mjs`、`node scripts/build.mjs`。测试脚本见 `package.json`。

终端没有配置 Node 的 PATH 时，可用现有 Node 的绝对路径替换 `node`。默认端口 4321，开发与构建预览分别启动；指定其他端口用 `node scripts/serve.mjs --port 4322`。需要通过 HTTP 预览，不直接双击 HTML。

## 主数据

每个 item 对应一个作品或活动对象，`id` 是稳定主键。重读、重看、再次参观时，在同一个 item 的 `history` 末尾追加事件，不新增重复 item。**只维护 `data/records.json` 这一个 JSON 数组**，不拆作品库与个人记录；筛选结果与年份选项均由它生成。Git 记录文件的编辑历史，体验的状态变化由 `history` 记录，二者不能互相替代。

| 字段 | 规则 |
| --- | --- |
| `id` | 唯一且稳定，小写字母／数字／`-`／`_`，以字母或数字开头；改标题不改 ID |
| `title` | 非空作品或活动名称 |
| `type` | 使用 [src/lib.mjs](src/lib.mjs) 的 `TYPES` 键名；运行 `npm run fields` 查看可填值和中文名称，影视包含电影与剧集 |
| `history` | 至少包含一个事件的数组，按实际发生顺序排列，允许状态重复；每项必须有 `status` 和 `date`，见下文 |
| `rating` | 可选，兼容旧记录的顶层评分；没有历史评分时才使用。新评分写入 `history`，无需同时修改顶层；有效值仍为 `0`–`5` 或 `null` |
| `comment` | 短评纯文本，可为空字符串 |
| `tags` | 无重复的非空字符串数组，没有标签用 `[]` |
| `url` | 外部作品／活动来源的链接数组，如 `["https://example.com/a", "https://example.org/b"]`；没有链接用 `[]`；每项必须是非空的完整 HTTP(S) 链接 |
| `review_url` | 博客长评的完整 HTTP(S) 链接或空字符串 |

顶层不再允许 `status`、`date`，事件格式如下（规则示意，不是现有示例的额外经历）：

```json
"history": [
  { "status": "completed", "date": "中学时代" },
  { "status": "in_progress", "date": "2026-10" },
  { "status": "completed", "date": "2026-11" }
]
```

- 事件 `status`：使用 [src/lib.mjs](src/lib.mjs) 的 `STATUSES` 键名，运行 `npm run fields` 查看当前枚举。不限制状态转换，也不要求先写计划状态。
- 事件 `date`：该状态发生的日期或时期，支持 `"2026"`、`"2026-10"`、`"2026-10-31"`、`"中学时代"`、`"2026年暑假"`；未知用 `null`，兼容空字符串。保留原精度，不补造经历或日期；不把备份时间、作品发行时间当作体验时间。
- 数组由维护者按实际发生顺序追加，不自动按日期排序；自定义时期和未知日期也保留原位置。
- **当前状态**取最后一个事件的 `status`，状态筛选使用它。
- **最新更新日期**取 `history` 最后一项的 `date`，与最后事件的状态无关。表格日期、时期搜索、年份筛选和默认排序均使用它；最后日期为空时显示“—”，不回退到更早日期。
- **展示评分**取最后一个非空的事件 `rating`，`0` 是有效评分，不因后续未评分事件而丢失。历史中均无评分时，兼容旧顶层 `rating`；两者都没有则不显示。事件评分允许 `0`–`5` 的有限数字（可有小数）或 `null`，也可以省略。
- 事件可选 `comment` 为字符串，`progress` 为对象：必填 `value`、可选 `total` 均为非负有限数字，可选 `unit` 为字符串，例如 `{"value":37,"total":336,"unit":"页"}`。顶层进度使用同样校验。
- 展开区按原有数组顺序展示每次状态、日期及已有事件评分、进度；空的可选信息不占位置。展开状态只保存在浏览器当前页面，不写入主数据。

其他字段仍属于整个作品或活动对象。`review_url` 仍是单个长评链接，`url` 仍是链接数组。

日期与筛选规则：

- 标准日期按日历校验；以 `YYYY` 或 `YYYY-` 开头的日期不能填成 `2026-02-30`、`2026-13` 等无效日期。
- 自定义时期是非空文本，原样显示，不推断具体年份。`中学时代`、`大学期间`、`2026年暑假` 均进入“自定义时期”筛选分组，可直接搜索具体文字。
- 年份选项只从有效的 `YYYY`、`YYYY-MM`、`YYYY-MM-DD` 提取；`null` 和空字符串进入“日期未记”。
- 默认先显示标准日期，按时间倒序；点击日期列头可切换升降序。两种顺序均将自定义时期置于标准日期之后、未知日期置于最后，同日期或同分组按稳定 ID 排列，不猜测不同人生阶段的先后。

可选 `author`（作者）、`lists`（书单／片单）均为非空字符串组成的数组，没有内容用 `[]`。地点、平台等按实际需要扩展，校验允许额外字段；已展示的已知字段会检查类型。新增类型或状态只修改 `src/lib.mjs` 的枚举，页面、校验与 `npm run fields` 共用它，不需要同步维护另一份清单。

## 新增记录

浏览器标题和页内标题固定为 `sanctum-media-log`。当前主数据均为正式记录。以后如临时使用虚构示例，必须加 `demo: true`；校验不允许示例与正式记录混用。

新增前先搜索现有作品与来源链接，避免重复 item；已有作品应追加 `history`。新作品往同一数组新增对象，例如下面的**填写模板**：

```json
{
  "id": "book-001",
  "title": "替换为真实作品名称",
  "type": "book",
  "history": [
    { "status": "planned", "date": null }
  ],
  "comment": "",
  "tags": [],
  "url": [],
  "review_url": ""
}
```

再次体验时找到原 item，保留 `id`，向 `history` 追加状态事件；如需评分，直接在对应事件中加入 `"rating": 4.5`，不再抄写到顶层；只知道一次体验就只写一项，未知日期填 `null`。不要用新增重复 item 或修改 Git 提交历史表示重读重看。

正式记录无需 `demo` 字段；不要通过删除示例标识把虚构经历当作真实记录。新增后运行校验、刷新预览。空数组也是正常状态，不会自动回填示例。

## 已整理的个人记录

2026-10-31 整理：豆瓣 900 条记录和 iPhone 备份的 222 条记录，整理并将日期短评转为历史后，共 **916 个作品、1124 个状态事件**，没有 demo。电影、电视剧统一为 `video`（影视），不再分别维护 `movie`、`tv`。

- 优先用豆瓣条目 ID 合并。另将 17 组同名同作者书籍的不同版本合并为作品，保留全部版本链接；同名影视改编仍按独立作品保留。新 ID 使用 `douban-book-<条目ID>` 或 `douban-video-<条目ID>`，以后不因标题、版本或日期变化而重建 ID。
- 按用户确认，不同日期均保留为独立事件；同一作品同日同状态的重复来源记录合并。同日有明确不同进度的事件仍保留，允许连续重复状态。日期按已存储时间排序，不把未记录的状态转换补成事件。
- iPhone 毫秒时间戳按 `Asia/Shanghai` 取日期，不猜测其中的年月日精度。状态 `1` 和《镜花缘》的 `-1` 对应 `planned`，`2` 对应 `in_progress`，`3` 对应 `completed`。该备份的评分 `0` 表示未评分，转为 `null`；手工维护时真实评分 `0` 仍有效。
- 事件统一使用 `date`。同日同状态来自多个来源时合并为一次；来源没有记录具体时间时，不补造同日事件的精确先后。
- 为保留已有个人信息，历史事件可带 `rating` 和 `progress`（`value`、可选 `total`、`unit`）；展示评分由最后一个有评分的事件自动推导；保留的旧顶层值仅供兼容，无需手动同步。相同事件的评分冲突优先保留豆瓣导出的非空值。不同短评按来源日期倒序保留并去重，标签仅使用个人标签。
- 实际存在的作者保存在可选 `author` 数组，个人书单／片单归属保存在可选 `lists` 数组；这些不增加页面或手工维护数据源。
- iPhone 的《雍正大传》只有作品资料，没有体验记录，未导入、未补造 `history`。另一个无 iPhone 体验记录的条目已由豆瓣提供历史。

## 备份与部署边界

原始 JSON、Excel 和附件私有保存在**仓库之外**，不复制进网站，不作为另一份日常维护数据。`.gitignore` 忽略 `imports/`、`backups/`、`private/`、Excel 和压缩包，作为防误放保护。

构建只复制 `src/` 与校验后的主数据到 `dist/`。资源使用相对路径，兼容 GitHub Pages 项目子路径。主数据中的内容会随网站公开。

部署流程在 [.github/workflows/pages.yml](.github/workflows/pages.yml)：推送 `main` 或在 GitHub Actions 手动运行后，使用 Node.js 22 执行语法、单元测试、数据校验／构建与浏览器回归检查，仅将 `dist/` 上传发布。测试或校验失败时停止发布；部署结果可在仓库 Actions 和 `github-pages` 环境中查看。无需本地提交 `dist/`，也不需要额外配置部署密钥。
